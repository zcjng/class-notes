# 🧱 Security Frameworks

## 📌 Definitions

- **Security frameworks** — *guidelines* used for building plans to help mitigate risks and threats to data and privacy.
- **Compliance** — the process of adhering to internal standards and external regulations; enables organizations to avoid fines and security breaches.
- **Security controls** — *safeguards* designed to reduce specific security risks. Used **with** security frameworks to establish a strong security posture. → see [[Security Controls]].
- **Security posture** — an organization's ability to manage its defense of critical assets and data and react to change. A strong posture leads to **lower risk**.

> [!TIP] Memory hook
> **Frameworks** = the *plan* · **Controls** = the *safeguards* · **Posture** = the resulting *defensive strength*.

## 📚 Major Frameworks & Standards Covered

| Framework / Standard | One-line purpose |
| :--- | :--- |
| **[[NIST Cybersecurity Framework\|NIST CSF]]** | Voluntary standards, guidelines & best practices for managing cybersecurity risk. |
| **[[NIST SP 800-53]]** | Unified control framework for US federal government information systems. |
| **[[ISO IEC 27001]]** | International standard for managing the security of assets. |
| **Cyber Threat Framework (CTF)** | Provides a **common language** for describing and sharing threat information. |

## ⚖️ Regulations vs. Compliance vs. Frameworks

| Concept | Nature | Example / note |
| :--- | :--- | :--- |
| **Regulation** | **Mandatory** rule from a government or regulator | HIPAA, GDPR, PCI DSS — fines, prosecution, brand damage if broken |
| **Compliance** | The **ongoing act** of adhering to internal standards and external regulations | A continuous state, not a one-off project |
| **Framework** | **Voluntary**, structured collection of guidelines, baselines, and best practices | NIST CSF — a blueprint you *choose* to meet legal and business objectives |

> [!TIP] One-liner
> Regulations are what you **must** do; frameworks are what you **choose** to use to do it.
