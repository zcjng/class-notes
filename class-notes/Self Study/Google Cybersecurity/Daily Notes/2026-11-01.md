## 📝 Raw Notes

### PKI & encryption (M2)
- **PKI** manages encryption methods *and* establishes trust. Asymmetric (public encrypts, private decrypts) is secure but slow; symmetric (one shared key) is fast but weaker.
- Real connections: asymmetric for the handshake (login, key exchange) → symmetric for the session.
- Longer keys = more brute-force resistance but slower processing.
- **3DES** 3×56-bit → effective 168-bit (legacy, data-volume limits). **AES** 128/192/256-bit — brute-forcing AES-128 ≈ billions of years. **RSA** 1,024/2,048/4,096-bit. **DSA** 2,048-bit (NIST, early 1990s).
- **OpenSSL** generates keys and verifies certificates. **Heartbleed (2014)** exposed memory contents — patched, but a lesson in patching.
- **Kerckhoff's principle**: everything about the algorithm except the private key can be public. Security through obscurity isn't security.
- **Digital certificates** = ID badges; a **CA** verifies identity and signs with its private key.
- Compliance: **FIPS 140-3**, **GDPR**.

### Hashing (M2)
- One-way, fixed-length digest; one character changed → completely different hash.
- Integrity + **non-repudiation**. Analysts hash files and check them against VirusTotal.
- **MD5** — 128-bit / 32 characters, broken by **collisions**. **SHA-1** 160-bit (deprecated), then SHA-224/256/384/512.
- Passwords must be hashed, never plaintext. **Rainbow tables** reverse common hashes; **salting** (random characters added pre-hash) defeats them.

### Access control (M2)
- **AAA** = Authentication → Authorization → Accounting.
- Factors: **knowledge / ownership / characteristic**.
- **SSO**: one login, better UX, lower cost, fewer attack points. Works via encrypted **access tokens** from a trusted identity provider — **LDAP** on-prem, **SAML** cloud.
- **MFA/2FA/3FA** must use *distinct* factor types.
- HTTP Basic Auth = plaintext credentials; HTTPS encrypts. **OAuth** shares designated access without passwords; **API tokens** carry identity + permission.
- Authorization frameworks: **MAC** (strict, central authority, need-to-know), **DAC** (owner decides), **RBAC** (role decides).
- **Accounting** tracks sessions. Session ID identifies user + device until logout/timeout; **session cookies** validate without resending credentials. **Session hijacking** = stolen ID/cookie.
- **IAM**: right user, right resources, right time, right reasons. **Provisioning** creates identity; **deprovisioning** removes access — don't skip it.

### CI/CD (M3)
- **CI** merges + builds + tests constantly. **Delivery** = always release-ready, manual gate to prod. **Deployment** = fully automatic to prod.
- Security in the pipeline: **DAST**, compliance checks, infrastructure validation, **SAST**, **SCA**.
- Vulnerabilities: insecure dependencies (CVEs), misconfigured permissions (fix with RBAC), no automated testing, **exposed secrets** (use a vault), unsecured build environments.
- **DevSecOps** = security in every stage; small frequent releases limit blast radius.

### Defense in depth (M3)
- Castle approach: moat → walls → watchtowers, each layer with *different* controls.
- Layers: perimeter (auth) → network (firewall/authorization) → endpoint (antivirus) → application (MFA) → data (classification/encryption).
- **Physical attack surface** (people, devices) vs. **digital attack surface** (everything online — cloud exploded this).
- **Hardening** shrinks the attack surface by removing unnecessary entry points.

### CVE ecosystem (M3)
- **Vulnerability** = inherent weakness · **exposure** = operational mistake/condition · **exploit** = the method used.
- **CVE List** — MITRE, 1999, open dictionary. Anyone reports; a **CNA** must approve.
- Four criteria: **independence**, **recognition**, **evidence**, **single codebase impact**.
- **NVD** (NIST) scores CVEs with **CVSS** 0–10: <4.0 low, >9.0 critical.
- **Vulnerability management cycle**: identify → analyze exploits → deploy controls → evaluate effectiveness, repeating.

### OWASP Top 10 (M3)
Broken access control · cryptographic failures · injection · insecure design · security misconfiguration · vulnerable/outdated components · identification & authentication failures · software & data integrity failures (SolarWinds) · logging & monitoring failures · SSRF.

### Scanning & patching (M3)
- Scanners compare known vulnerabilities against network technologies; non-intrusive but can crash fragile systems.
- **External** (perimeter) vs. **internal** (internal systems); **authenticated** (real/admin account) vs. **unauthenticated** (simulates outsider); **limited** (specific devices) vs. **comprehensive** (everything). Run **discovery** first.
- Patching: **manual** (control, but things get forgotten) vs. **automatic** (CISA recommends, but vendor quality varies). **EOL software** never gets patches.
- Assessment lifecycle: **identification → vulnerability analysis → risk assessment → remediation**.

### Pen testing (M3)
- Authorized simulated attack = ethical hacking. Required by **PCI DSS, HIPAA, GDPR**.
- **Red** attacks, **blue** defends, **purple** collaborates.
- **Open-box** (full knowledge/white-box), **closed-box** (zero knowledge/black-box), **partial** (gray-box).
- **Bug bounties** pay freelancers — HackerOne is the main hub.

### Attacker mindset (M3)
- APT = long-term unauthorized access, usually nation-state, focused on surveillance.
- Threat actor motivations: competitors, state actors, criminal syndicates, insider threats, shadow IT.
- Hackers: unauthorized (incl. script kiddies), authorized/ethical, semi-authorized (hacktivists).
- Vectors: direct access, removable media, social media, email, wireless, cloud services, supply chains.
- 4-step mindset: **identify target → determine access → evaluate vectors → find tools and methods**.

### Social engineering (M4)
- 4 stages: **prepare → establish trust (pretexting) → persuade → disconnect**.
- Baiting (USB), phishing, **quid pro quo** (fake reward), **tailgating** (following someone in), **watering hole** (compromised frequently-visited site — Holy Water 2020).
- Phishing kits: malicious attachments, fake data-collection forms, fraudulent links.
- Channels: email, **smishing** (SMS), **vishing** (voice). Variants: spear phishing, whaling, **angler phishing** (fake customer service on social media).
- Defences: training, blocklists/allowlists, IPS on email, anti-phishing policies.

### Malware (M4)
- **Virus** (needs human action) vs. **worm** (self-propagating — Blaster/Lovesan). **Trojan** disguises and delivers payloads. **Ransomware** announces itself. **Spyware** is silent.
- **Adware/PUA**, **scareware** (fake warnings), **fileless** (lives in memory, needs memory analysis), **rootkit** (dropper + loader), **botnet** (bot-herder), **cryptojacking** (CPU spikes, battery drain, power bills).

### Web exploits (M4)
- **XSS**: reflected (via link), stored (on server), DOM-based (browser only, URL params). Steals cookies, geolocation, webcam access.
- **SQLi**: in-band (same channel), out-of-band (separate channel — rare), inferential/blind (infer from behaviour/errors).
- Fixes: **sanitize input**, **prepared statements**.

### Threat modeling (M4)
- Risk treatment: **avoid · reduce · transfer · accept**.
- PASTA 7 stages: objectives → technical scope → decomposition (DFDs, trust boundaries) → threat analysis → vulnerability analysis → attack modelling → risk & impact.
- Frameworks: **STRIDE** (Microsoft, mapped to authn/integrity/non-repudiation/confidentiality/availability/authorization), **PASTA**, **Trike** (permissions/privilege), **VAST** (visual, agile, automated).
- Five questions: what are we working on → what can go wrong → what are we doing → did we cover everything → did we do a good job.
