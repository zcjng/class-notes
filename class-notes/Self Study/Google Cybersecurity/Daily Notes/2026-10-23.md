## 📝 Raw Notes

### Risk planning (M1)
- **Three elements:** assets (something valuable), threats (events that harm assets), vulnerabilities (weaknesses a threat exploits).
- Threats = **intentional** (malicious hacker) or **unintentional** (employee holds the door open). Vulnerabilities = **technical** (misconfigured software) or **human** (lost access card).
- **Risk** = anything impacting the **CIA** of an asset. $\text{Likelihood} \times \text{Impact} = \text{Risk}$.
- Bank matrix example: likelihood scored **1 rare / 2 likely / 3 certain**; no severity below 2; a **financial records leak scored 9** → remediate first.

### Asset management
- "You can only protect what you know you have." Types: **digital**, **information systems**, **physical**, **intangible** (IP, brand, trade secrets).
- Classify by answering: **what / where / who owns / how important**. Benefits: risk prioritization, cost optimization, compliance (ISO 27001, SOC 2, HIPAA).
- Levels: **Restricted → Confidential → Internal-only → Public**.
- Challenges: **ambiguous ownership** (work laptop holding personal files) and **data aggregation** (billing statement mixes public + confidential).

### Cloud (M1 refresher + depth)
- NCSC: "on-demand, massively scalable service on shared infrastructure, accessible via the internet." Drivers: scalability, agility, CapEx → OpEx.
- Responsibility: **SaaS** (vendor runs everything), **PaaS** (you own code/data), **IaaS** (you own OS and up). CSP responsibility grows IaaS → PaaS → SaaS, but **data, IAM, and credentials are always yours**.
- Challenges: **misconfiguration** (exposed buckets), cloud-native breaches (IAM roles, API gateways, metadata endpoints), visibility gaps, cross-border compliance.
- Data states: **in use**, **in transit**, **at rest**.

### Security planning (M1)
- Security = **people, processes, technology** — a culture, not an IT task.
- **Policies** (strategic: what & why) → **Standards** (tactical: benchmarks, e.g. 8-char minimum per NIST SP 800-63B) → **Procedures** (operational: step-by-step SOPs).
- **Regulations** = mandatory (HIPAA/GDPR/PCI DSS) · **compliance** = ongoing adherence · **frameworks** = voluntary blueprints you choose.

### NIST CSF (M1)
- Created **2014** for U.S. critical infrastructure; now global.
- Pillars: **Core** (6 functions: Govern, Identify, Protect, Detect, Respond, Recover) · **Tiers 1–4** (Partial → Risk Informed → Repeatable → Adaptive) · **Profiles** (current vs. target → gap analysis).
- CISA workflow: **Current Profile → Risk Assessment → Gap Analysis → Action Plan**. Keep it live, not an annual checkbox.

### Controls & privacy (M2)
- Controls: **technical** (encryption, MFA, firewalls, ACLs) · **operational** (awareness training, audits, IR drills) · **managerial** (policies, compliance benchmarks, SOPs).
- **Information privacy** = protection from unauthorized access/distribution — the **right to choose** when/how/to what extent data is shared.
- **PoLP**: minimum permissions for the minimum time (CS rep can see a booking temporarily; marketing cannot see card numbers).
- **Privacy** = giving people control over their data · **InfoSec** = keeping data safe in all states.

### Data governance (M2)
- Lifecycle: **Collect → Store → Use → Archive → Destroy** (keep data recoverable at every stage).
- Roles: **owner** decides access/edit/destroy · **custodian** handles transport, storage, maintenance (can be a person, team, or automated system) · **steward** enforces policy.
- Protected data: **PII** (name, address, phone) → **SPII** (bank numbers, credentials — need-to-know) and **PHI** (health, HIPAA/GDPR).
- **Audit** ~yearly, internal + external, verifies compliance · **assessment** every 3–6 months, usually internal, tests resilience, often preps for an audit.

### Cryptography (M2)
- Plaintext → **encryption + key** → ciphertext → **decryption + key** → plaintext. **Cipher** = the algorithm.
- **Caesar cipher**: shift letters (`HELLO` → `KHOOR` with shift 3). Weak: only 25 shifts → brute force without the key; one leaked key exposes everything.
- Key management: keep keys private, transmit keys **separately** from the encrypted message.
