## 📝 Raw Notes

### Detection signatures (C6 M4)
- Three components, in order:
    1. **Action** — what the IDS does when conditions match: `alert`, `pass`, `drop`, `reject`.
    2. **Header** — protocol, source and destination IPs/ports, direction. Newer rules use variables like `$HOME_NET` and `$EXTERNAL_NET`.
    3. **Rule options** — parentheses, semicolon-separated: `msg`, `sid`, `rev`, `flow`, `content`.
- Tuning is the analyst's real work: generic rules = false positives.

### Suricata
- Runs as **network- or host-based IDS**, as an **IPS**, or as a **network security monitoring (NSM)** tool.
- Can analyse **live traffic or pcaps** — useful for IR, forensics and testing signatures.
- Config: **`/etc/suricata`**, rules in the **`rules`** subfolder, `#` = commented-out rule.
- **`suricata.yaml`** sets environment details and **rule evaluation order** — default **pass → drop → reject → alert**.
- Logs: **`eve.json`** (EVE JSON — key-value, metadata-rich, feeds a SIEM) and **`fast.log`** (basic legacy alerts).
- **Alert logs** vs **network telemetry logs**: telemetry (e.g. an `http` event with hostname, user agent, content type) records normal flow too — combine both to reconstruct the sequence.

### SIEM pipeline & ingestion (C6 M4)
- Pipeline: **collect → normalize → index** → query.
- **Indexing** is what makes fast searching possible.
- **Ingestion** = copying and storing event data from generating sources into the SIEM. Copying **preserves the original source logs** so they aren't modified during analysis.
- Manual collection doesn't scale — **log forwarders** (OS-native, third-party, or proprietary/SIEM-integrated) automate it.
- Platforms: **Splunk Enterprise Security** (collect, index, search, analyze, visualize) and **Chronicle** (forward, normalize, index, query).

### Splunk (SPL)
- `index=main fail` — index + keyword.
- `fail*` wildcard catches `failed` / `failure`; quotes force exact phrase; `OR` searches multiple terms; `|` pipes output into the next command.
- Interface: timeline for peaks, events viewer for raw records, metadata (host / source / sourcetype), exclusion filters like `host!=www1`.
- Broad searches are slow — always constrain by index, event ID, and time range.

### Google SecOps / Chronicle
- **YARA-L** for detection rules.
- **UDM search** (default) over normalized parsed data — fast. Fields grouped as **Entities, Event metadata, Network metadata, Security results**.
- Example: `metadata.event_type = "USER_LOGIN" AND security_result.action = "BLOCK"`.
- **Raw log search** for unparsed data, ingestion troubleshooting, and regex/hash/filename matching — slower.
- Results: timeline bar graph, event list with assets, click through to the raw log, quick filters (e.g. target IP).

### Regex (C7 M3)
- `import re` → `re.findall(pattern, text)` returns a list of all matches.
- Symbols: `\w` alphanumeric + underscore · `\d` digit · `\s` whitespace · `\.` literal period · `.` any character.
- Quantifiers: `+` one or more · `*` zero or more · `{2}` exact · `{1,3}` range.
- Email pattern: `\w+@\w+\.\w+`. Composite: `\w+:\s\d+` (label, colon, space, number).
- Used for log parsing, Chronicle raw log search, Wireshark's `matches` operator, and `grep`.
