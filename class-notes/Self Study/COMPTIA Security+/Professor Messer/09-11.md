# Professor Messer 1.2 | CIA Triad

## CIA Triad

Confidentiality
- Prevent disclosure of information to unauthorized individuals or systems
- Uses Encryption
- Limit access by implementing access controls
- 2FA 
Integrity
- Recepient receives exactly what was sent, messages cant be modified without detection
- Using Hashing can tell easily
- Digital signature
	- Also can use Digital SIgnature, takes hash and then encrypts it with an asymmetric encryption algorithm
- Certificates, combined with Digital Signature to verify an individual
- **Non-repudiation,** has proof of integrity, can be asserted to be genuine, actually came form the originated party
Availability
- Everything remains up and running
- Redundancy, build services that will always be available
- Fault tolerance, system continue to run even when a failure occurs
- Patching systems, ensures system are as stable as possible, and close security holes

## Non Repudiation
When someone sends data, the recepient should be able to verify whether it actually came from the sender

- Sign a contract
	- Your signature adds non-repudiation
	- You really did sign the contract
	- Others can see the signature
- Cryptography
	Which is the practice and study of securing information by converting readable data (plaintext) into an unreadable format (ciphertext) so only authorized parties can read or process it
	- Uses proof of integrity
		- Any data we receive we can verify its the same that was sent
		- Data remains accurate and consistent
		
	- Proof of origin, with high assurance of authenticity

## Proof of Integrity
- **HASH,** represent data as short string of text (message digest/fingerprint)
		- If anything changes with the datam the hash changes.
		- But hashes, doesnt associate data with the particular individual that sent it.

## Proof of Origin
- Authentication, proving the source of the message, by using a Digital Signature
- Sign with the private key, only known to the person that is sending the data
- To verify, we use the public key associated with the private key

# Professor Messer 1.2 | AAA

Log In is a process of AAA

Begins with

Identification
- Who you claim to be
- Usually your username
Authentication
- Proves you are who you say you are
- Password, or other authentication factor
Authorization
- What access do you have based on your identification and authentication
Accounting
- Resources you used, like logs

In a network system, in order to authenticate a device
- Put a digitally signed certificate on the device
Other business processes will need to rely on the certificate
- Access to the VPN from authorized devices
- Management software can validate the end device

An org has a Certificate Authority (CA)
- device or software that is responsible for managing all of the certificates in our environment

**On the CA also has its own cert thats signed by the root CA**
- we create a cert for that laptop, that cert is now digitally signed by that CA, so later we can verify that its an original cert from CA

Everytime we want to do auth, we can use the CA certificate

How to authorize?
- Use authorization model
- Authorize users and services -> data and apps 
- We can use roles, organizations, attributes

Writing permissions for each and every one can be cumbersome and not scalable.

- Add an abstraction (groups)
	- Reduce complexity
	- Create a clear relationship between the user and the resource
- Administraton is streamlined
	- Easy to understand the authorizations

# Professor Messer 1.2 | Zero Trust

Once you're through the firewall, there sometimes are little security controls

Zero trust fixes that,
- Hollistic approach
- Covers every device, every process, every person
- Everything must be verified
- Nothing is inherently frusted

Planes of operation
- Split the network into functional planes, applies to physical virtual and cloud components
	- Data plane -> performing the actual security process
		- Switch, router, firewall
		- Processes packets, frames and network data in real time.
		- Processing, forwarding, trunking, encrypting, NAT
		- Anything that moves one data from one part of the network to another
	- Control plane -> Manages the action of the data plane
		- Policies and rules for the devices of the data plane
		- Determine how packets should be forwarded
		- Configuring control plane: routing tables, session tables, NAT tables
![[Pasted image 20261109141425.png]]


We have to be smart on how we evaluate the security controls
- Adaptive identity:
	- Apply security controls based on the authentication process, and what the user is doing
	- Source and the requested resources
	- Physical location, type of connection, IP address, etc
	- Make authentication stronger if needed
- Threat scope reduction
	- Decrease the number of possible entry points, like minimizing attack surface
- Policy driven access control
	- Combine the adaptive identity with the predefined set of rules

Security Zones:
- Where are people connecting from?
	- Trusted, untrusted
	- Internal network, External network
	- VPN 1, VPN 5, VPN 11
	- Marketing, IT, Accounting
- Set rules on what zones have access to what other zones
- Some zones are implicitly trusted: Trusted -> Internal zone traffic

Policy enforcement points (PEP):
- The gatekeeper, decides to allow, monitor, terminate connection on
- Subjects and systems (end users, application, non human entities)
