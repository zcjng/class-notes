# Professor Messer 2.4 | Overview of Malware

> [!NOTE] Definition
> **Malware** is any software that does something bad to your system — stealing keystrokes, showing ads for profit, encrypting your files, or giving an attacker remote control.

---

### 1. The Malware Family

- **Categories:** viruses, worms, ransomware, Trojan horses, rootkits, keyloggers, spyware, bloatware, logic bombs
- **Common outcomes:** turn the system into a botnet, steal personal data, encrypt everything on the drive
- Malware is rarely one single event — the pieces work together

### 2. How Infections Chain Together

> [!WARNING] Layered Infection
> One piece of malware rarely does all the work. Each stage opens the door for the next.

- A **worm** exploits a known vulnerability and installs itself on the storage drive
- That installs additional malware, such as a **remote access backdoor**
- The attacker connects to the backdoor and pushes more malware for extra capabilities

### 3. How It Gets In

- Clicking a link or attachment in email → loader runs in memory and uses the CPU
- Pop-up on a malicious website
- **Drive-by download** — content downloads automatically without any click (relatively rare)
- A worm propagating itself using a known vulnerability
- Undiscovered vulnerabilities exist in every OS and app → keep everything patched

### 4. Why Malware Exists

- Your data has value: family photos, archives, documents
- In an organization: planning documents, employee PII, financial details
- Value comes from the data itself, or from what you're willing to pay to get it back

### 5. Ransomware

- Encrypts all data on the machine, then demands payment for the decryption key
- The OS keeps working normally on purpose — the attacker needs you to see the payment message
- Payment is usually cryptocurrency; a decryption key is sent after payment

> [!IMPORTANT] Two Fundamental Best Practices
> **Offline backups** — ransomware can't encrypt a backup it can't see. **Patching** — OS and applications.

- Anti-malware / antivirus identifies malicious code using **signatures** → keep signatures updated to catch the newest variants

# Professor Messer 2.4 | Viruses and Worms

> [!NOTE] Definition
> A **virus** is malicious code that replicates itself from one computer to another but requires some intervention (usually a human clicking a link or running an executable) to start. A **worm** is malware that self-replicates across systems with **no user intervention** at all.

---

### 1. Virus Behavior

- Once running, it moves through the local file system and can try to reach file systems across the network
- Most viruses cause outages and downtime, but some sit quietly in the background and go unnoticed
- Antivirus runs continuously, watching executables for known-bad code → signature file must stay updated

### 2. Virus Types

- **Program / executable virus:** starts when the user clicks a link or runs an application
- **Boot sector virus:** sits in the boot sector and runs automatically as the system boots
- **Script virus:** browsers, the OS, and many applications execute scripts that can carry malicious code
- **Macro virus:** written in the macro language of an app like Microsoft Office, abusing that app's vulnerabilities
- **Fileless virus:** never writes malicious code to storage

### 3. Fileless Viruses

> [!WARNING] Living in Memory
> Most antivirus looks for things being written to disk. A fileless virus writes nothing to disk, so it evades that check entirely — everything happens in RAM.

- Typical chain:
  1. User clicks a malicious link in email or on a website
  2. The site exploits a vulnerability in the OS or an app (Flash, Java, a known Windows flaw)
  3. The virus runs a built-in tool like **PowerShell**, which downloads and executes more scripts in memory
  4. It installs other apps, removes data, and exfiltrates it to a third party
- Persistence: since nothing is on disk, it adds an **autostart registry entry** so the whole process repeats after a reboot

### 4. Worms

- Self-replicate across systems with no user interaction
- Networked systems make this extremely efficient — worms spread at the **speed of the network**
- Can attack any time, since no user needs to do anything
- **Network firewalls, personal firewalls, and IPS** with up-to-date signatures are what identify and stop the propagation

### 5. Case Study: WannaCry

- A worm that also installed ransomware, encrypting all user files
- An infected machine scanned the network for other vulnerable systems
- **EternalBlue** installed a backdoor, pulled down the ransomware code, and infected the machine
- The worm then continued hunting and infecting every vulnerable system on the network

# Professor Messer 2.4 | Spyware and Bloatware

> [!NOTE] Definition
> **Spyware** is malware that watches everything happening on your system. **Bloatware** is unnecessary software preinstalled by the hardware manufacturer.

---

### 1. Spyware

- Capabilities: puts advertising on screen, steals personal information, commits **affiliate fraud** on your online purchases
- Installation vectors (similar to a virus): peer-to-peer software, **fake security software**, malicious links in email
- Monitors browsing habits and reports back to attacker servers
- Often bundles a **keylogger** — everything typed (usernames, passwords) is collected into a file and sent to the attacker

### 2. Dealing With Spyware

- Anti-malware / antivirus recognizes and blocks it before execution
- Research anything before installing it — every install is an opportunity for malware
- Spyware embeds itself deeply in the OS and some versions are very hard to uninstall
- **Known good backup** so you can recover
- Third-party tools such as **Malwarebytes** can identify and often remove it

### 3. Bloatware

> [!WARNING] Security Concern on a Brand-New Device
> Bloatware is preinstalled by the manufacturer, usually because the vendor was paid to include it. A new out-of-the-box device may already have exploitable software on it.

- Examples: extra games, security tools, utilities you never asked for — not part of a core OS install
- Concerns:
  - Wastes storage that could go to real applications
  - Many entries auto-start and reduce overall system efficiency
  - Any of them may have a known or unknown vulnerability

### 4. Removing Bloatware

- Manually: look in installed applications and use the **Uninstall** button
- Some apps ship their own uninstaller in the Program folder or Start menu
- Third-party uninstaller utilities exist when nothing else works — a last resort, not the first choice

# Professor Messer 2.4 | Other Malware Types

> [!NOTE] Definition
> Additional malware categories that don't fit cleanly into virus/worm/spyware: **keyloggers**, **logic bombs**, and **rootkits**. Each targets a different layer of the system.

---

### 1. Keyloggers

- Attackers know the keyboard is where the sensitive data enters the machine
- Captures: URLs visited, usernames, passwords, credit card and financial details
- Stays resident on the system, logs to a file, and sends that file to the attacker once or more per day

> [!WARNING] The Unencrypted Point
> We encrypt data in transit (VPN/TLS) and at rest (full disk or file encryption), but **typing is not encrypted**. That makes the keyboard a perfect capture point.

- Also grabs: clipboard contents, screenshots, instant message/chat content, search engine queries
- **DarkComet** is a RAT (Remote Access Trojan) that includes this keylogging functionality — it even logged spaces and backspaces to reconstruct the typed word

### 2. Logic Bombs

- Waits for a specific event, then detonates: a date and time, or a particular user logging in
- Payload can reboot the system, erase data, or change configuration
- Usually written by an insider or someone with a specific goal, never deployed to another system first → **no antivirus signature exists**, which makes it very hard to identify
- Detection and defense:
  - Monitoring tools that watch critical OS files for modification
  - Change control procedures that limit who can alter core OS files
  - Least privilege — someone without extra rights can't easily plant one

**Case Study — South Korea, March 20, 2013:** A malicious email with an attachment installed a Trojan on bank and broadcaster systems. The next day at 2:00 PM local time the logic bomb triggered, deleting everything in storage plus the **master boot record**, then rebooting. Systems — including the bank's ATMs — came back up with "Boot device not found. Please install an operating system on your hard disk."

### 3. Rootkits

> [!DANGER] Part of the Operating System
> "Root" comes from the Unix superuser. A rootkit usually hides in the **kernel**, so it becomes part of the OS itself — it won't appear in a task/process list and traditional antivirus can't see it.

- While running, anything the OS does includes the malicious code → full control of the computer
- Not all rootkits are kernel-level; ones running as a normal process may still be detectable by anti-malware
- **Standalone rootkit removal tools** exist per variant — useful after infection, but they don't prevent the initial compromise
- **Secure Boot** (UEFI BIOS) checks for a valid OS signature and verifies nothing has changed in the kernel before the system boots, stopping the rootkit from running even if it got installed

# Professor Messer 2.4 | Physical Attacks

> [!NOTE] Definition
> A **physical attack** ignores the OS and its vulnerabilities entirely and attacks the hardware or the environment around it.

---

### 1. Why Physical Matters

- Someone with physical access to a computer can gain **full control** of that system
- If they can touch it, they can circumvent the OS running on it
- "Door locks only keep out the honest people" — physical controls need additional layers

### 2. Brute Force

- Normally a password term, but also a physical technique: forcing open a locked door or window
- Worth evaluating against your data center — how hard would it be to force a door or window that leads to the whole infrastructure?

### 3. RFID Cloning

- Access badges and key fobs commonly use RFID underneath
- Cloning an existing badge gives the same access rights as the owner
- Cheaper and easier than expected: RFID cloners/duplicators sell on Amazon for under $50 US
- Duplication takes seconds — read one card, write to another
- Documented cases of brushing up against someone on a train with a reader and walking away with a duplicate

> [!IMPORTANT] MFA Is the Countermeasure
> Even with a cloned badge, the attacker doesn't know your PIN and doesn't have your biometrics, so the duplicated card alone won't get them in.

### 4. Environmental Attacks

- If you can't attack the systems, attack the environment around them
- **Power:** cut power to the data center — can often be done from outside the building without any door access
- **HVAC:** usually a lower security priority. Taking over HVAC control and killing the cooling lets systems overheat and shut down automatically
- **Fire suppression:** in some data centers triggering it sets off a chain of events that produces a denial of service

# Professor Messer 2.4 | Denial of Service

> [!NOTE] Definition
> A **denial of service (DoS)** occurs when an attacker intentionally forces a service to fail — by overloading it so no one else can get in, or by exploiting a known vulnerability or design failure.

---

### 1. Motivation and Methods

- Motivations: outright disruption, competitive advantage (removing a competitor from the internet), or a **smokescreen** while another vulnerability is exploited elsewhere
- Keep systems patched — many DoS conditions come from known vulnerabilities
- Sometimes trivially simple: removing power from a system

### 2. Self-Inflicted DoS

- Plugging two switches into each other twice creates a **loop** — without spanning tree, that part of the network goes down
- Downloading a large file (e.g., a Linux distribution) over a small DSL line consumes all bandwidth your production apps need
- A water line run above the ceiling of the data center that breaks

### 3. Distributed Denial of Service (DDoS)

> [!WARNING] Asymmetric Threat
> The attacker has comparatively few resources but can take down organizations with far more systems and bandwidth by using other people's devices.

- Attackers don't rely on one device — they use many devices worldwide
- Malware on those devices creates **botnets** (robot networks) under the attacker's control
- One command to the botnet launches the attack
- **Zeus botnet** had over 3.6 million computers under control at its peak
- Sending large amounts of data to the target brings it down faster

### 4. Reflection and Amplification

- Small requests get turned into large responses using services available to anyone
- Protocols that respond with more data than was requested: **NTP**, **DNS**, **ICMP**
- Example: a `dig` query for `isc.org` sends ~15 characters and receives ~1,300 characters back — about **86x amplification**
- Attack flow:
  1. Command and control sends one command to the botnet
  2. The attacker picks **open DNS resolvers** (poorly configured/unsecured, scattered worldwide)
  3. The botnet sends spoofed queries (source = victim's IP) to those resolvers
  4. The resolvers send their much larger responses to the victim's web server, overwhelming it

# Professor Messer 2.4 | DNS Attacks

> [!NOTE] Definition
> We rely on DNS to turn a fully qualified domain name into an IP address. **DNS poisoning** makes a user resolve a name to an IP address they never intended to reach.

---

### 1. Ways to Poison DNS

> [!WARNING] Easiest Path Wins
> Modifying the DNS server itself is hard — those servers are well protected. Attackers usually go after something more accessible.

- **Modify the DNS server record:** requires admin credentials or a known vulnerability on the server OS. This is not the common case
- **Modify the client's local hosts file:** contains FQDNs and IP addresses, and the machine checks it *before* querying DNS. Requires access to the client and usually elevated rights
- **On-path interception:** sit in the middle of the conversation, intercept the DNS query, and reply with a malicious answer. Requires real-time positioning

### 2. Poisoning With IP Spoofing (Example)

- Normal: User 1 queries the DNS server (`162.159.246.164`) for `professormesser.com`, gets the legitimate `.164` answer, caches it
- Attack: the attacker (`100.100.100.100`) gains access to the DNS server and rewrites the record so `professormesser.com` now points to `100.100.100.100`
- Result: every subsequent request — e.g. from User 2 — goes to the attacker's computer instead of the real site

### 3. Domain Registration Hijacking

- Access to the **domain registration** lets the attacker control where all traffic for that FQDN goes
- Not simple — registrars have security in place — but reachable via brute force, social engineering, or credentials leaked publicly online
- **Case Study — Brazil, Saturday, October 22, 2016, 1:00 PM:** 36 domains in a bank's registration settings were changed, covering desktop, mobile, and other devices. Attackers had access for six hours over the weekend and effectively *became* the IP address for the entire bank, collecting usernames, passwords, and financial data. The bank (5 million+ customers, ~$27 billion in assets) released nothing about the incident

### 4. URL Hijacking (Typosquatting / Brandjacking)

- Exploits misspellings users make when typing a domain
- **Examples:** `professormesser.com` vs. `professormessor.com` (M-E-S-S-O-R); leaving off the final S; adding letters (`professormessers.com`); same name on a different TLD (`.org` instead of `.com`)
- Why attackers do it:
  - Ad revenue from the redirect
  - Sell the misspelled domain back to the legitimate owner
  - Redirect the traffic to a competitor
  - Present an exact-looking copy of the site to harvest credentials
  - Deliver ransomware or recruit the device into a botnet

> [!IMPORTANT] Defense
> Don't click links in email, and look closely at the domain before you trust the page you're on.
