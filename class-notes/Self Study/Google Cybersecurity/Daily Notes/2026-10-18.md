## 📝 Raw Notes

### DoS & DDoS
- **DoS** = flood a network/server to disrupt operations — attacker wins if *any* part is overloaded.
- **DDoS** = multiple devices across locations; far more likely to overwhelm the target.
- **SYN flood** = unfinished TCP handshakes → open ports exhausted · **ICMP flood** = bandwidth eaten by replies · **Ping of death** = oversized ICMP (>64 KB) crashes reassembly.

### Packet sniffing
- Passive = read only (easy on hubs) · Active = alter/inject packets · **Promiscuous mode** = NIC accepts all traffic, not just its own MAC.
- Tools: **tcpdump** (CLI, libpcap), Wireshark, SolarWinds NetFlow, ManageEngine OpManager, Azure Network Watcher. Output: timestamp, source/dest IP & port.

### IP spoofing family
- Spoofed source IP → bypass firewall rules, hide origin.
- **On-path** = sit between endpoints, impersonate, can do **DNS spoofing** · **Replay** = delay/repeat auth traffic · **Smurf** = spoofed ICMP to broadcast → every host replies to the victim.

### Brute force & prevention
- **Simple brute force** = guess combinations · **Dictionary** = common/stolen password lists.
- Prevention (defense-in-depth): **HTTPS/VPNs** for data in transit · firewall **ingress filtering** (drop external packets claiming internal IPs) · NGFW anomaly detection · no open public Wi-Fi without a VPN.
- Hardening: **hashing** (one-way) + **salting** (random chars before hashing) · **MFA** (≥2 factors) / **2FA** · **CAPTCHA** vs bots · password policies (complexity, rotation, history, lockout thresholds).

### Vulnerability assessment
- **VMs**: isolation, disposable images, snapshot/revert — small **virtualization escape** risk.
- **Sandboxes**: run untrusted software, test patches; modern malware can **detect sandboxes** and play dead.

### Cloud security
- Cloud challenges: loose IAM configs, complex configs, expanded attack surface, rapid CSP updates.
- **Shared responsibility**: customer = security **in** the cloud (data, IAM, apps, OSes); CSP = security **OF** the cloud (data centers, hypervisors). The **assumptions trap** = assuming the CSP covers something that's yours.
- Hardening: tighten IAM, hypervisor isolation, **baselining** normal behavior, **cryptographic erasure** (destroy keys) when decommissioning.
- CSPs find zero-days earlier; visibility via **flow logs** & **packet mirroring**; independent **third-party audits** because backend servers can't be inspected directly.

### Operating systems (Course 4 start)
- OS bridges **hardware ↔ user**, translates interactions into **binary**.
- Modern OSes multitask and manage peripherals; **Linux** is the security industry's primary tool.
- OS security covers files, data access, authentication; analysts configure access, firewalls, policies, virus protection, auditing/logging.
- **Legacy OS** = outdated but still used (embedded software dependencies); unpatched = exposed to new threats.
